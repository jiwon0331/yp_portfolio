# Featured Projects 미표시 진단

기존 v2 소스와 수정 후 배포본을 로컬 HTTP 서버에서 확인했습니다. 실제 공개 사이트 URL은 제공되지 않아 공개 서버의 파일 누락·캐시는 확인하지 않았습니다.

## 진단 결과

1. projects.json 로드: HTTP 200, 총 8개.
2. 상대 fetch 경로: `/`, `/portfolio/`, `/portfolio/index.html`에서 정상. 하위 경로에서는 `/portfolio/data/projects.json`을 요청합니다.
3. 렌더링: 주요 카드 4개와 추가 경험 4개 모두 표시.
4. 빈 heroImage/images가 카드 렌더링을 막는 조건: 없음.
5. 이미지 없는 프로젝트를 제외하는 필터: 없음. 이미지 항목 자체만 검증합니다.
6. ID: 8개 모두 고유하고 유효함. 기존 주요 카드 검증은 제목·ID가 잘못되거나 ID가 중복된 항목을 제외하므로 새 데이터를 추가할 때도 고유 ID가 필요합니다.
7. JSON 문법: 정상.
8. 정상 HTTP 페이지에서 JavaScript console error 및 pageerror: 없음.
9. 분류: group이 additional이면 추가 경험, 나머지는 주요 프로젝트. featured는 강조·우선 배치에 사용하며 false라고 제외하지 않습니다.

## 재현된 현상과 수정

- 현재 유효한 데이터에서 일부 카드 미표시는 재현되지 않았습니다. 공연장 등 4개 항목은 삭제된 것이 아니라 Additional Experience에 있습니다.
- HTML 파일을 file://로 직접 열면 브라우저 제한으로 fetch가 실패하여 전체 프로젝트가 표시되지 않습니다. 로컬 웹 서버 또는 배포 주소로 열도록 오류 문구를 명확히 했습니다. 이 환경 제한을 이미지 문제로 간주하지 않았습니다.
- overview가 없으면 summary·responsibilities 등 다른 상세 데이터도 가리던 조건을 발견했습니다. openProjectDialog에서 항상 createCaseStudy를 호출하고, overview는 summary로 보완하거나 빈 개요 부분만 생략하도록 수정했습니다. 현재 4개 주요 프로젝트에는 overview가 있어 기존 카드 누락의 원인은 아닙니다.
- js/projects.js만 기능 보정했습니다. CSS·HTML·실제 프로젝트 내용·분류·fetch 상대경로는 유지했습니다.

## 현재 이미지 규칙

- 유효한 프로젝트 데이터는 이미지 유무와 무관하게 표시합니다.
- 유효한 heroImage가 있으면 대표 사진을 표시하고 없거나 유효하지 않으면 이미지 컨테이너를 만들지 않습니다.
- images에 유효한 이미지가 있을 때만 갤러리를 표시합니다. 값이 없거나 null 또는 빈 배열이어도 텍스트 상세는 표시합니다.
- 이미지 로드 실패는 이미지 영역만 제거합니다. 카드와 텍스트는 유지합니다.
- 이미지 경로·alt 검증과 같은 출처 제한은 유지합니다. 외부 이미지나 임의 placeholder는 추가하지 않았습니다.

이미지 누락·null·빈 값·잘못된 이미지 객체·정상 이미지의 5개 검수 데이터에서 모두 카드와 텍스트가 유지되는 것을 확인했습니다. 검수 데이터는 실제 projects.json에 저장하지 않았습니다.
