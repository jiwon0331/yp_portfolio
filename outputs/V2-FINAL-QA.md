# v2 최종 QA 보고서

검수일: 2026-09-30. 로컬 Edge 브라우저에서 GitHub Pages와 같은 `/portfolio/` 하위 경로로 빌드 결과를 검수했습니다. 실제 기기·스크린리더 사용자 테스트 및 공개 서버 검수는 수행하지 않았습니다. 실제 배포는 수행하지 않았습니다.

## 1. v2에서 변경된 사항

- 상위 섹션을 01 Experience Journey → 02 Featured Projects → 03 Skills → 04 Interest & Learning → 05 About → 06 Contact로 통일했습니다. Journey 내부 숫자는 없습니다.
- 영어 UI 제목에 작은 한국어 제목을 붙이고 핵심 역량·전공을 병기했습니다. 본문 전체를 두 언어로 반복하지 않으며 SPSS, Excel, Canva 등 도구 이름은 유지했습니다.
- What I Bring은 4개 역량과 15개 실제 경험 근거로 구성했습니다. 관련 사례를 여는 연결도 유지했습니다.
- Journey는 학업·학회·학생회 → Sweden Exchange → KOICA 프로젝트 봉사단 → 사업 운영 관심의 4단계입니다.
- 주요 프로젝트는 KOICA → 복지관 실습 → 연구·분석 → 우수 졸업논문 순서입니다. KOICA는 전체 폭 대표 카드이며 추가 경험은 작은 제목과 간결한 목록으로 구분했습니다.
- 사진은 경험 ID별 폴더와 `heroImage`, `images`로 관리합니다. 사진 없는 항목은 빈 이미지 영역을 표시하지 않습니다.
- Skills에 제공된 수준·자격 근거를 반영하고 Learning은 현재 기여 역량과 앞으로 배울 영역을 구분했습니다.
- About 원문 3문단을 유지했습니다. Contact에는 전화·이메일만 연결했고, footer에 요청한 한영 AI 안내를 작게 표시했습니다.

## 4. 아직 placeholder 상태인 콘텐츠

우수 졸업논문 상세의 아래 4개 값만 의도적으로 노출합니다.

- `[THESIS TITLE TBD]`
- `[RESEARCH QUESTION TBD]`
- `[METHOD TBD]`
- `[KEY FINDING TBD]`

대표 설문 연구를 졸업논문과 동일한 연구로 간주하지 않았습니다. 모든 경험의 `heroImage: null`, `images: []`는 현재 사진 미등록 상태이며 화면에는 placeholder를 표시하지 않습니다. 일부 미제공 기간·장소·역할 필드도 비어 있으나 빈 사실 항목은 렌더링하지 않습니다. Contact와 Resume 준비 중 문구는 없습니다.

## 6. 발견한 문제 및 개선 권장사항

### 수정한 문제

- 추가 경험 갤러리에서 모든 사진 로드가 실패하면 빈 갤러리 컨테이너가 남을 수 있었습니다. 마지막 이미지가 제거되면 해당 컨테이너도 제거하도록 수정하고 검증했습니다.
- 모달 기본 정보의 Role 표기를 Role / 역할로 통일했습니다.

### 콘텐츠 검토 결과

| 점검 항목 | 평가·근거 |

### 30초 관점 검토

실제 채용담당자를 대상으로 시간을 재어 평가한 결과가 아니라 화면의 정보 위계를 기준으로 한 검토입니다.

| 파악할 내용 | 위치·평가 |
|---|---|
| 사회복지·심리 전공 | Quick Profile — 명확함 |
| 국제개발협력 분야 지원 | Hero 역할·헤드라인 — 명확함 |

모바일에서는 Evidence 15개를 30초 안에 모두 읽기는 어렵습니다. 핵심 배경·방향은 먼저 전달되지만 상세 근거는 추가 읽기용입니다. 현재 요청된 문구를 유지했으며, 다음 개편에서 필요하다면 역량별 핵심 근거를 먼저 보여주고 나머지를 펼치는 방식을 검토할 수 있습니다.

### 기능·접근성·반응형 검증

- 375·430·768·1024·1440px 모두 페이지 및 모달 가로 넘침 없이 통과했습니다.
- 모든 주요 메뉴와 활성 상태, 본문 바로가기, 주요 카드·관련 사례 버튼을 확인했습니다.
- 모달 초기 초점, Tab·Shift+Tab 초점 유지, ESC·Close·배경 클릭 닫기, 배경 스크롤 잠금, 닫은 뒤 초점 복귀를 확인했습니다.
- 프로젝트 순서, 추가 경험 4개, 섹션 번호, 단일 h1, 제목 단계, 고유 ID, 내부 앵커 목적지를 확인했습니다.
- 실제 화면에는 빈 이미지 영역이 없으며, 검수용 임시 데이터로 대표 사진 1개·갤러리 5개 표시와 alt 지원을 확인했습니다. 검수 이미지는 프로젝트 데이터에 저장하지 않았습니다.
- 이미지 속성 누락, 갤러리 오류 후 제거, reduced-motion 설정을 추가 확인했습니다.
- 주요 텍스트·배경 색상 조합의 최소 대비는 5.30:1입니다. 링크와 동작 버튼을 구분하고 키보드 포커스 스타일을 유지합니다.
- 검수 범위에서 스크립트 예외·실패한 정상 리소스 요청이 없었습니다. 전화·이메일 링크는 주소를 확인했으며 실제 연락은 하지 않았습니다.

### 남은 권장사항과 한계

- 논문 TBD 4개와 실제 사진·결과물은 사용자가 제공해야 합니다.
- 홍보 수치의 집계 기간·비교 기준·팀과 개인 기여 범위를 실제 자료와 함께 명시하면 신뢰도가 더 높아집니다. 임의 기준은 추가하지 않았습니다.
- 영문은 UI·개념 병기 수준이며 전체 영문 포트폴리오는 아닙니다.
- v2 Lighthouse는 재측정하지 않았습니다. 기존 v1 점수를 v2 점수로 사용하지 않았습니다. 실제 배포 후 성능 측정과 실제 모바일·스크린리더 확인이 필요합니다.
