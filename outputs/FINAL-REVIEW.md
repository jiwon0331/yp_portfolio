# 최종 채용담당자 관점 검토

## 종합 판단

기술적으로 GitHub Pages 배포가 가능하도록 정리했습니다. 공개 배포는 수행하지 않았습니다. 첫 화면에서 지원 분야와 현장 경험이 확인되고, 핵심역량의 Evidence 버튼으로 실제 사례에 바로 접근할 수 있습니다. 다만 이력서 PDF와 연락처가 없어 채용 제출 콘텐츠는 아직 완성되지 않았습니다.

## 변경 사항과 이유

- 요청한 title·description을 정확히 반영하고 Open Graph, 1200×630 공유 이미지, 실제 favicon을 추가했습니다. 없는 파일을 참조하는 SEO placeholder를 남기지 않았습니다.
- 핵심역량의 '관련 프로젝트 준비 중'을 JSON에 정의된 실제 사례 링크로 교체했습니다. 초반에 주장과 근거가 연결되도록 했습니다.
- KOICA 성과 4개를 대표 카드에서도 보여주고 성과 범위를 함께 표시했습니다. 개인이 사업 전체를 관리한 것으로 해석되지 않게 했습니다.
- Resume의 준비 중 상태를 화면에도 표시했습니다. 작동하는 이력서 링크처럼 보이는 혼선을 줄였습니다.
- 미사용 스타일과 불필요한 이벤트 발행 코드를 정리하고, 공통 metric 렌더러로 카드·상세의 중복 코드를 줄였습니다.
- 모바일 메뉴의 첫 렌더링 상태를 미리 정해 레이아웃 이동을 줄이고, 화면 문구가 접근성 이름에 포함되도록 보완했습니다.
- 배포용 파일만 복사하는 빌드와 수동 GitHub Pages 워크플로를 추가했습니다. work·검수 자료·도구는 공개 사이트에서 제외합니다.

## 사용자 확인이 필요한 콘텐츠

1. **수정 필요 — 연락처·Resume:** 실제 이메일 또는 연락 방법과 PDF를 제공해야 채용 담당자가 연락하거나 이력서를 열 수 있습니다.
2. **성과 수치의 근거:** 게시물 수, 조회, 프로필 방문, 팔로워 증가의 집계 기간·출처·비교 기준 및 팀/개인 기여 범위를 확인해야 합니다. 현재 수치는 사용자가 제공한 내용 그대로입니다.
3. **활동·연구 정보:** KOICA 활동 기간, 연구 프로젝트명·기간·구체 주제, 정확한 학업 정보는 공개할 내용이 확정되면 추가할 수 있습니다.
4. **실제 결과물:** 공개 가능한 운영표, 홍보물, 전시·영상 화면, 연구 산출물과 설명이 있으면 11번의 근거 제시가 강화됩니다. 현재 Gallery는 비어 있습니다.
5. **기술·언어 경험:** 영어·스페인어, 도구와 SPSS 방법을 실제로 어느 과제에서 사용했는지 확인해 면접 설명과 일치시킵니다.
6. **배포 주소:** 저장소 이름·계정·도메인은 미정입니다. 실제 Pages 빌드가 올바른 절대 URL을 주입하도록 구성했습니다.

## 배포 준비

README의 GitHub Pages 절차를 따라 저장소에 소스를 업로드하고 Settings → Pages → GitHub Actions를 선택한 뒤 수동 워크플로를 실행합니다. 원격 저장소는 아직 만들거나 연결하지 않았습니다.

구현 기준: [GitHub 공식 Pages 사용자 정의 워크플로 문서](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## 최종 기술 검증 결과

- Lighthouse 13.5.0, 로컬 Edge 모바일 에뮬레이션 최종 측정: **Performance 64 / Accessibility 100 / Best Practices 100 / SEO 100**.
- **Performance 90+ 목표 미달**입니다. 주요 진단은 메인 스레드의 스타일·레이아웃 작업 및 로컬 서버의 압축·캐시 미설정입니다. 이전 수정본 측정에서는 96점도 나왔지만 이를 최종 점수로 사용하지 않았습니다. 실제 배포 환경의 결과로 재확인해야 합니다.
- 최종 보고서에서 화면 문구와 접근성 이름 불일치 문제는 해소됐습니다. 점수 100이 수동 접근성 검토나 실제 보조기기 검증을 대체하지는 않습니다.
- 375·430·768·1024·1440px에서 가로 넘침·모달 범위·메뉴·키보드·지표·Evidence·Gallery를 확인했습니다. 정상 로드에서 콘솔 오류와 실패한 내부 파일 요청이 없었습니다.
- 저장소 하위 경로 `/portfolio/`에서 상대 경로가 정상 동작했습니다. 실제 배포 URL을 canonical·og:image·sitemap에 주입하는 빌드도 테스트했고 테스트용 주소는 최종 파일에서 제거했습니다.
- 배포 ZIP에 `.github/workflows/pages.yml`, 빌드 스크립트, 이미지, 정적 소스가 포함되며 `work`, 검수 도구와 node_modules는 제외됩니다.
- Resume `href="#"`는 의도한 비활성 placeholder이며 '준비 중' 표시가 있습니다. 실제 이력서와 연락처 추가는 사용자가 완료해야 합니다.
- 실제 GitHub 배포·공유 미리보기·공개 서버 Lighthouse 검사는 아직 수행하지 않았습니다.
